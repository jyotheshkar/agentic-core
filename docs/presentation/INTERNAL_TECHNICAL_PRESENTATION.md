# Agentic Core: Internal Technical Presentation Outline

1. Problem: personal agent systems become unreliable when authority, evidence, and completion claims are blurred.
2. Architecture: MOA orchestrates, Minister judges, Scout evidences, Forge builds, Audit reviews, and the Skill Broker chooses reusable methods.
3. Runtime truth: composition is host-mediated and `EMULATED`, not native plugin-to-plugin process execution.
4. Control plane: registries, bounded handoffs, state ledger, conflict ownership, verification gates, audit chain, and recovery semantics.
5. Capability decisions: Audit is the visible fifth standalone agent. Fix, Design, Launch, and Lab remain composed workflows unless a future non-overlapping authority earns standalone status.
6. Evidence: component regressions, contract tests, integration demo, source/cache parity checks, and privacy/security scans.
7. Safety: user retains consequential external action authority; free-first; no secrets or personal operational data in the repository.
8. Limitations and next steps: test actual runtime installation and cache parity after an intentional source migration; do not misstate the emulated composition boundary.
