# MOA Architecture

MOA is the top-level orchestrator. Minister is the mandatory decision authority, Scout is the research evidence authority, Forge is the engineering authority, Skill Broker selects trusted shared expertise, and completion governance controls claims.

`request -> intent psychology -> problem framing -> Minister initial judgment -> capability discovery -> Agent Registry and Skill Broker -> execution graph -> execution -> verification -> Minister final judgment -> completion governance`

## Participation levels

| MOA level | Use | Current Minister adapter |
| --- | --- | --- |
| LIGHT | Tiny, reversible, low-risk implementation | LIGHT |
| STANDARD | Normal bounded project or decision | STANDARD |
| DEEP | Consequential, uncertain, or multi-lens judgment | COUNCIL |
| CRITICAL | Difficult-to-reverse life, legal, immigration, or major financial decision | CRITICAL |

MOA composes installed skills in the current Codex task. The platform does not expose a plugin-to-plugin process API, so separate autonomous plugin execution is not claimed.

## Authority

- MOA: who participates, sequencing, parallelism, scope, and handoffs.
- Minister: what should be done and whether the outcome is strategically acceptable.
- Scout: what current evidence establishes, contradicts, or leaves unknown.
- Forge: how software is designed and implemented.
- Audit: independent assurance of supplied artifacts, evidence, policy conformance, release readiness, residual risks, and completion claims.
- Shared skills: advisory specialist methods.
- Verification: evidence that acceptance criteria are met.
