# MOA Problem Framing

Classify the task as DECIDE, BUILD, RESEARCH, AUDIT, FIX, DESIGN, LAUNCH, EXPERIMENT, PLAN, COMPARE, ANALYSE, or MIXED. Reframe only when evidence shows the requested activity is not the bottleneck, such as repeated research when the real blockage is choosing.

Return REQUEST, REAL PROBLEM, DESIRED OUTCOME, TASK TYPE, CONSTRAINTS, ACCEPTANCE CRITERIA, and DECISION-CRITICAL UNKNOWNS. Preserve the user's authority and explicit scope. A reframe informs Minister and routing, it does not silently replace the request.
