# Frontend Engineering

## Workflow

1. Inspect the existing stack, browser targets, design contract, data interfaces, and states.
2. Use semantic HTML and platform behavior before custom abstractions.
3. Keep state ownership explicit and component boundaries aligned to behavior.
4. Test keyboard use, reflow, loading, error, empty, and slow-network states across target widths.

## Output contract

A tested frontend implementation with documented state and accessibility behavior.

State evidence, assumptions, uncertainty, and missing capability separately when they affect the result. Stop or defer when a decision-reversing unknown cannot be resolved safely.

## Boundary

Do not claim accessibility or cross-browser support without current checks on the implemented result.

This skill is advisory expertise. MOA owns orchestration, Minister owns strategic judgment, Forge owns engineering implementation, and verification owns completion evidence.

## Evidence basis

Use the relevant parts of the [primary guidance](https://developer.mozilla.org/en-US/docs/Learn_web_development) when standards or formal evidence are material. Verify currency before making a time-sensitive claim.
