# Red-Team Protocol

## Challenge map

Build a compact argument map: conclusion, supporting claims, evidence, assumptions, dependencies, and external actors. Attack the nodes whose failure would most change the conclusion.

## Evidence attacks

Check provenance, freshness, directness, incentives, independence, selection effects, missing comparisons, base-rate neglect, and whether the evidence supports causation or only correlation. Do not claim a source was checked when it was not.

## Strategy attacks

Test timeline realism, resource sufficiency, coordination burden, counterparty response, concentration risk, lock-in, exit cost, and whether the plan optimizes a proxy instead of the objective.

## Consensus challenge

State the strongest reason the group may share the same error: common source, shared incentive, authority pressure, social proof, sunk cost, or excluded stakeholder. Treat this as a hypothesis requiring evidence.

## Repair standard

For each decisive challenge, specify the smallest test, evidence, redesign, condition, or contingency that would resolve it. Separate fatal flaws from repairable weaknesses.

End by identifying what still survives the attack. A red team that cannot acknowledge survival is not calibrated.
