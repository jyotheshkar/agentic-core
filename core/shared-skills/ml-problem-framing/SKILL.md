# ML Problem Framing

## Workflow

1. State the desired outcome in non-ML terms and identify who can act on the output.
2. Compare ML with rules, search, workflow, and manual baselines.
3. Define model input, output, unit of prediction, constraints, and failure costs.
4. Separate product success metrics from model evaluation metrics and set a baseline.

## Output contract

An ML framing brief with suitability decision, baseline, objective, data needs, and success thresholds.

State evidence, assumptions, uncertainty, and missing capability separately when they affect the result. Stop or defer when a decision-reversing unknown cannot be resolved safely.

## Boundary

Do not choose ML merely because data exists or generation is possible.

This skill is advisory expertise. MOA owns orchestration, Minister owns strategic judgment, Forge owns engineering implementation, and verification owns completion evidence.
